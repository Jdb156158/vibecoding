什么是 Vibe Coding

一句话：用嘴写代码。

你不需要懂变量声明、函数调用、数据库连接，只需要把需求描述清楚。核心闭环是「描述 → 生成 → 测试 → 反馈」：跑通了就过，跑不通就换个说法再试。

  • 对程序员是提效工具，对非程序员是直接把「原本过不去的坎」铲平；
  • 2023–2025 属于大模型，2026 属于 AI 智能体——国内代表 WorkBuddy，国外代表 Codex；
  • 两者的核心玩法都是 Skill 生态：一份说明书教 AI 一项新本事。
工具会一直换，但攒下来的技能库是自己的。

双平台对比

大卖场与精品店——两种生态哲学。

维度WorkBuddyCodex

共同点SKILL.md 是通用标准，Claude Code / Codex / WorkBuddy / Cursor 认同一份文件

Codex 技能机制速览：一个 skill = 一个文件夹（SKILL.md + 可选脚本），启动时预加载名字和描述，干活时自己判断用哪个。装完问一句「你现在有哪些技能」，识别了才算装上。官方目录在 openai/skills。

#坑说明与对策

        
          
1技能装太多，判断失准每个技能都消耗上下文窗口，装多了模型选择时判断失准。按需安装，不用的及时关掉。

          
2装上 ≠ 生效装完问一句「你现在有哪些技能」，识别了才算装上。

          
3Vibe Coding ≠ 听天由命AI 改完直接点确认不叫 Vibe Coding。小步快跑：小功能 → 生成 → 测试 → 报错反馈再改。

          
4省敲代码时间，不省思考时间给 AI「问题」而不只是「结果」：给谁用、解决什么、凭什么。描述精度决定产出质量。

          
5Demo 陷阱上生产前补六件事：接 CMS、接表单/支付、接数据、补边界、查响应式、做优化。

          
6能跑但不知为何能跑安全、边界、错误处理 AI 不主动替你考虑；资金/隐私/核心业务不适用一句话生成。

          
7跨平台复用零成本SKILL.md 标准通用，复制或软链接即可在四家工具间迁移。
